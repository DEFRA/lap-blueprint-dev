# Security Access Request

If an security exception is required this guidance sets out how to submit a Security Exception to Policy Request (a "Security Waiver") where a supplier, contractor or project resource needs access to Defra systems, services or environments but cannot meet the required security clearance prerequisites at the point they are due to start work.

A waiver allows Defra Security to assess the risk and decide whether a temporary exception can be granted while security validation is completed. A waiver is a temporary exception only and is not a substitute for obtaining the correct level of clearance. If the individual's SC clearance application is rejected at any stage, the waiver is immediately revoked and the individual must be removed from the project.

## When a Security Waiver is required

Consider requesting a waiver where:

- A resource states they hold SC clearance, but Defra has not yet validated or transferred it.
- Security evidence has not been submitted to the Defra Vetting and Security Team before onboarding.
- Defra needs further evidence about a supplier’s vetting process before recognising the clearance.
- An urgent delivery requirement could be affected by delays in security validation.
- There is a business-critical requirement that means the project cannot wait for the SC clearance process to complete before work needs to commence.

There must be a clearly documented business-critical reason demonstrating why project delivery would be adversely impacted if the resource could not start work before SC clearance is granted.

## Before you request a waiver

Confirm the following before raising a request:

- Existing Clearance: Where an individual already holds SC clearance, evidence must be provided to the Defra Vetting and Security Team, who will validate it and may contact the previous sponsoring organisation to confirm it can be transferred.
- Existing Application: An SC clearance application must already be in progress ("in flight") before an SC waiver request can be submitted.
- BPSS: Where BPSS has been completed, evidence may be required and suppliers may be asked to demonstrate their vetting process.
- Device and Access: Requirements may vary across Defra organisations and ALBs. Some areas may permit access on a Defra-managed device where BPSS is met or supplier devices needing connectivity may attract additional scrutiny.
- Location Requirement: Location requirements may vary depending on the DEFRA organisation, security classification, access method, and hosting environment. In some circumstances, resources may be required to be UK-based and utilise a DEFRA-managed device as part of the security assessment. Project teams should confirm any location-specific requirements with the DEFRA Vetting and Security Team before submitting a Security Exception to Policy Request.

Completing security onboarding before mobilisation helps avoid delays to account creation, VPN access and delivery.

## How to request a waiver

1. Identify the requirement: the programme team, PMO, supplier or delivery lead confirms that a resource cannot meet an access prerequisite and that delivery may be affected.
2. Ensure an SC application is already in progress: Confirm that the individual has an active SC clearance application and has received confirmation that the application is being processed before proceeding with a waiver request.
3. Engage Defra Security: contact the Defra Vetting and Security Team and explain the business requirement, the resource, the delivery impact, and the resource’s current security status.
4. Candidate submits documentation: the resource completes the required security documentation and submits it directly to the Defra Vetting and Security Team. Because of its sensitive nature, it must not be reviewed or retained by programme or project teams, except where the reviewing individual already holds SC clearance, they may review and progress the request as appropriate.
5. Security validation: the team verifies the information, validates any existing clearances, confirms whether they can be transferred, and carries out any further checks needed.
6. Security decision: Defra Security decides whether to approve the waiver, request further evidence, or reject it pending completion of standard clearance.
7. Access granted: access is enabled only after written confirmation is received from Defra Security.
8. Monitor clearance outcome: If the associated SC clearance application is rejected for any reason, the waiver must be immediately revoked and the individual must be removed from the project and any associated access arrangements withdrawn

## Access restrictions during review

Unless explicitly authorised by Defra Security, the individual must not access the Defra network, use Defra credentials, be granted VPN access, or access protected Defra services or environments. Teams should assume that no access can be provided until written confirmation is received.

## Indicative timescales

| Activity                      | Indicative timescale              |
| ----------------------------- | --------------------------------- |
| Security Waiver assessment    | Approximately 2 to 4 working days |
| New SC clearance applications | Approximately 8 to 12 weeks       |

Actual timelines depend on the responsiveness of employers, suppliers and security stakeholders.

## Roles and responsibilities

- Supplier: ensure resources meet contractual security requirements, provide accurate information, share evidence when requested, and complete vetting before mobilisation.
- Programme Team / PMO: verify onboarding is complete before mobilisation, escalate where delivery timelines may be affected, engage Defra Security when an exception is needed, and keep track of approved exceptions.
- Project Manager: may generally assume onboarding checks are complete before resources are assigned; security compliance sits at programme and supplier level.
- Defra Vetting and Security Team: review evidence, carry out verification activities, assess the associated risk, and approve or reject requests.

## Key points to remember

- A waiver is an exception process only, not a planned onboarding route.
- Wherever possible, complete all security evidence and vetting before a resource joins a programme or project.
- Requirements can differ across Defra and other ALBs. Always confirm local requirements before mobilising resources.
