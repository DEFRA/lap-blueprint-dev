## P-001: How to Set Up the Scanner for a Project

| Field                      | Details                                                                                                                                                                                                                                                                                                                                                                     |
| -------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| What You Are Trying To Do  | Get the scanner ready so your team can run reliable checks on a target codebase.                                                                                                                                                                                                                                                                                            |
| Who This Is For            | Project managers, product owners, delivery leads, and engineers preparing a new project.                                                                                                                                                                                                                                                                                    |
| Step-by-Step               | 1. Confirm the project has a local copy of the LAP PII Screener repository.<br>2. Ask the delivery engineer to run setup once to install required components.<br>3. Confirm the scanner status check returns healthy.<br>4. Decide whether advanced scanning (SonarQube and NLP) is needed for this project.<br>5. Record setup completion in the project onboarding notes. |
| Decision Flow              | Need quick baseline only: use default setup and proceed.<br>Need deeper security analysis: enable SonarQube setup.<br>Need person-name and location detection: enable NLP setup.                                                                                                                                                                                            |
| Who To Contact             | Repository maintainers through the project support channel.<br>Delivery engineering lead for environment setup support.                                                                                                                                                                                                                                                     |
| Governance / Approval Gate | No formal approval gate, but setup completion should be recorded before scan results are used for governance decisions.                                                                                                                                                                                                                                                     |
| Related Risk Theme         | R-01: Tool readiness and onboarding delay.                                                                                                                                                                                                                                                                                                                                  |
| Related Agent/Tool Links   | [Agent Catalogue](../agent-catalogue/)<br>[Tool Catalogue](../tool-catalogue/)                                                                                                                                                                                                                                                                                                |

## P-002: How to Run a Baseline Sensitive Data Scan

| Field                      | Details                                                                                                                                                                                                                                                                            |
| -------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| What You Are Trying To Do  | Identify personal data, secrets, and security issues in a project before release or AI-assisted processing.                                                                                                                                                                        |
| Who This Is For            | Project managers, product owners, compliance coordinators, and engineers.                                                                                                                                                                                                          |
| Step-by-Step               | 1. Select the project folder to scan.<br>2. Run a baseline scan using default scanners.<br>3. Generate an HTML report for stakeholder sharing.<br>4. Review findings by severity (critical, high, medium, low).<br>5. Assign high and critical findings for immediate remediation. |
| Decision Flow              | If critical findings exist: pause risky activities and assign urgent fixes.<br>If only low/medium findings exist: schedule remediation in normal sprint planning.<br>If no findings: capture evidence and proceed.                                                                 |
| Who To Contact             | Security/compliance representative in your delivery team.<br>Engineering lead for remediation assignment.                                                                                                                                                                          |
| Governance / Approval Gate | Projects should complete this scan before code is shared with external AI tools or moved toward release.                                                                                                                                                                           |
| Related Risk Theme         | R-02: Hidden PII and secret exposure.                                                                                                                                                                                                                                              |
| Related Agent/Tool Links   | [Agent Catalogue](../agent-catalogue/)<br>[Tool Catalogue](../tool-catalogue/)                                                                                                                                                                                                       |
| Status                     | Published                                                                                                                                                                                                                                                                          |

## P-003: How to Produce and Share Decision-Ready Reports

| Field                      | Details                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| What You Are Trying To Do  | Create clear evidence for governance, audit, and delivery decisions.                                                                                                                                                                                                                                                                                                                                                                              |
| Who This Is For            | Project managers, product owners, compliance leads, and governance forums.                                                                                                                                                                                                                                                                                                                                                                        |
| Step-by-Step               | 1. Choose the report type based on audience:<br>- HTML for leadership packs and stakeholder review.<br>- Markdown for collaboration platforms.<br>- JSON for automation pipelines.<br>2. Generate the selected report from the latest scan.<br>3. Confirm sensitive values are masked unless there is an explicit need to reveal them.<br>4. Attach the report to project governance records.<br>5. Track trend changes between reporting cycles. |

| Who To Contact             | Project governance coordinator.<br>Product owner for prioritization decisions.                                                                                                                                                                                                                                                                                                                                                                    |
| Governance / Approval Gate | Reports that expose raw sensitive values must be tightly controlled and should only be shared on approved secure channels.                                                                                                                                                                                                                                                                                                                        |

## P-004: How to Obfuscate Sensitive Values Safely

| Field                      | Details                                                                                                                                                                                                                                                                                       |
| -------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| What You Are Trying To Do  | Replace sensitive data in code with safe substitute values, while retaining a recovery path.                                                                                                                                                                                                  |
| Who This Is For            | Project managers overseeing remediation, and engineering teams executing the change.                                                                                                                                                                                                          |
| Step-by-Step               | 1. Run obfuscation in review mode.<br>2. Approve, skip, or edit each replacement in the guided review screen.<br>3. Save the review session for traceability.<br>4. Apply approved replacements.<br>5. Keep the generated backup path for rollback.<br>6. Re-scan and confirm risk reduction. |
| Decision Flow              | Need preview only: use dry-run mode.<br>Need realistic fake values for testing: use faker strategy.<br>Need quick urgent remediation: use severity auto-approve with caution.                                                                                                                 |
| Who To Contact             | Engineering lead for change control.<br>Security/compliance representative for sign-off decisions on unresolved items.                                                                                                                                                                        |
| Governance / Approval Gate | High-impact replacements should be reviewed before production deployment. Rollback capability must be retained until validation is complete.                                                                                                                                                  |
| Related Risk Theme         | R-04: Unsafe remediation and accidental code impact.                                                                                                                                                                                                                                          |
| Related Agent/Tool Links   | [Agent Catalogue](../agent-catalogue/)<br>[Tool Catalogue](../tool-catalogue/)                                                                                                                                                                                                                  |

## P-005: How to Roll Back and Recover Quickly

| Field                      | Details                                                                                                                                                                                                                                                      |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| What You Are Trying To Do  | Restore original files if obfuscation changes need to be reversed.                                                                                                                                                                                           |
| Who This Is For            | Delivery leads and engineers responsible for release safety.                                                                                                                                                                                                 |
| Step-by-Step               | 1. Locate the backup directory generated during obfuscation.<br>2. Run rollback using that backup reference.<br>3. Verify key files are restored.<br>4. Re-run a scan to confirm the restored state.<br>5. Capture lessons learned and update decision logs. |
| Decision Flow              | If rollback succeeds: continue with revised remediation plan.<br>If backup missing: restore from source control and repeat review.                                                                                                                           |
| Who To Contact             | Engineering lead and release manager.                                                                                                                                                                                                                        |
| Governance / Approval Gate | Rollback should be part of the formal safety plan whenever automated replacement is used.                                                                                                                                                                    |
| Related Risk Theme         | R-05: Delivery disruption due to failed remediation.                                                                                                                                                                                                         |
| Related Agent/Tool Links   | [Agent Catalogue](../agent-catalogue/)<br>[Tool Catalogue](../tool-catalogue/)                                                                                                                                                                                 |
